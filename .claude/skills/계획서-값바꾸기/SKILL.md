# 계획서 값 바꾸기

## 받는 것
- `raw/`의 계획서 1개 (.hwp 또는 .hwpx). 암호가 걸린 파일과 워드(.docx)는 다루지 않는다.
- 사용자가 대화로 준 "이전 값 → 새 값" 목록. 목록이 없으면 먼저 묻는다.

## 지킬 조건
- `raw/` 원본은 읽기만 한다. 작업 전후 `sha256sum`이 같아야 한다.
- 결과는 `out/`에만 새 파일로 만든다. 같은 이름이 있으면 덮어쓰지 않고 끝에 `_v2`(그다음 `_v3`)를 붙인다.
- kordoc은 파일을 외부로 보내지 않는다. kordoc은 `npx -y kordoc@^4`로만 쓴다(처음 한 번 내려받기는 허용됨).
- 단, Claude가 명령 결과로 읽은 내용은 대화로 Claude에 전달된다. 그래서 기본은 아래 **조용한 모드**로 하고, 문서 내용은 필요할 때만 읽는다.
- 바꾸면 안 될 것 같은 값(전화번호 속 숫자, 비슷한 금액 등)이 이전 값과 겹치면 바꾸기 전에 사용자에게 알린다.

## 조용한 모드 (기본)
프로젝트 폴더의 `값바꾸기.sh` 한 줄로 처리하고, 그 출력만 읽는다. 출력에는 진행 단계, 통과·실패, 바뀐 줄 수, 결과 파일 경로만 나온다.

- 문서 전체: `bash 값바꾸기.sh raw/<파일> "이전=>새" ...`
- 쪽 지정: `bash 값바꾸기.sh -p <쪽범위> raw/<파일> "이전=>새" ...`
- 제목 범위: `bash 값바꾸기.sh -s "<범위>" raw/<파일> "이전=>새" ...`
- 연습·시험이라고 하면: 위 명령에 `-o 연습`을 붙여 결과를 `out/` 대신 `연습/`에 둔다 (`.gitignore`에 있어 커밋되지 않음). 연습이 끝나면 `연습/` 폴더째 지워도 된다.

지킬 것
- `out/…_변경목록.md`, `out/…_점검실패.md`는 **열지 않는다.** 사용자에게 파일 경로를 알려 주고, 바뀐 줄을 직접 확인해 달라고 한다.
- 제목을 못 찾으면 출력에 문서의 **제목 목록**이 나온다(제목만 Claude에게 보임). 그 목록에서 고르게 한다.
- 점검 실패(종료 코드 1)면 결과는 `out/`에 저장되지 않는다. 이유는 `_점검실패.md`에 있다고 알리고, 사용자가 "자세히 봐 줘"라고 하면 그때 연다.
- 사용자가 "자세히 보여 줘", "바뀐 줄 보여 줘"라고 하면 그때 변경목록을 읽거나 아래 **자세히 모드**로 한다.
- 사용자가 내용을 아예 Claude에게 보이고 싶지 않다고 하면, 위 명령을 **터미널에서 직접** 돌리는 법을 알려 준다.

## 자세히 모드 (사용자가 원할 때)
작업 폴더 `W`는 스크래치패드(없으면 임시 폴더)에 만든다. `S`는 이 스킬 폴더다.

1. 원본 해시를 적고, 원본을 `W/원본.<확장자>`로 복사한다.
2. 마크다운으로 읽는다: `npx -y kordoc@^4 W/원본.<확장자> -o W/편집.md`
3. 값을 한 번에 바꾼다(긴 값 먼저, 바뀐 값은 다시 안 바꿈):
   `node S/replace.mjs W/편집.md W/편집.md "이전=>새" ...`
4. 원본 서식 그대로 반영한다(로그를 남긴다):
   `npx -y kordoc@^4 patch W/원본.<확장자> W/편집.md -o W/결과.<확장자> 2>&1 | tee W/patch.log`
   - .hwp를 넣으면 결과도 실제로는 .hwp다. 결과 확장자를 넣은 것과 같게 한다.
   - "0개 변경"이면 실패로 보고 멈춘다.
5. .hwpx면 구조 검사: `npx -y kordoc@^4 validate W/결과.hwpx` 통과해야 한다.
6. 점검한다: `bash S/check.sh -l W/patch.log W/원본.<확장자> W/결과.<확장자> "이전=>새" ... > W/점검.md`
   - 종료 코드 0이 아니면 결과를 `out/`에 두지 말고 사용자에게 알린다.
7. `out/`에 둔다:
   - `out/계획서_YYYY-MM-DD.<확장자>` ← `W/결과.<확장자>`
   - `out/계획서_YYYY-MM-DD_변경목록.md` ← `W/점검.md` (맨 위에 원본 파일 이름과 날짜를 적는다)
8. 원본 해시를 다시 확인하고, 바뀐 줄 목록을 사용자에게 보여 주며 "잘못 바뀐 줄이 있는지" 확인을 부탁한다.

## 쪽을 정한 경우 ("1쪽만", "2~4쪽만") — 자세히 모드
위 순서에서 3·6단계만 바꾼다.

3. 쪽 그림을 그린 뒤, 정한 쪽의 줄에서만 바꾼다:
   - `npx -y kordoc@^4 render W/원본.<확장자> -d W/pages --silent`
   - `node S/page_replace.mjs W/편집.md W/pages <쪽범위> W/편집.md "이전=>새" ...`
   - 종료 코드 1(쪽을 찾지 못한 줄이 있음)이면 그 줄을 사용자에게 보여 주고 멈춘다. 쪽 경계에 걸친 문단일 수 있다.
6. 점검에 쪽범위를 준다: `bash S/check.sh -l W/patch.log -p <쪽범위> ...`
   - 정한 쪽에서는 이전 값이 0이 되고, 다른 쪽은 건수가 그대로여야 통과한다.
   - 정한 쪽에 없는 값은 실패로 나온다. 값 모양(띄어쓰기, 점)이 문서와 같은지 사용자에게 확인한다.
- 결과 파일 이름에 쪽을 붙인다: `out/계획서_YYYY-MM-DD_1쪽.<확장자>`, `out/계획서_YYYY-MM-DD_1쪽_변경목록.md`
- 한계를 알린다: 여기서 "쪽"은 kordoc이 그린 쪽이다. 한글에서 저장한 파일은 한글의 쪽 정보를 쓰지만, 그 밖의 파일은 한글 화면의 쪽과 조금 다를 수 있다.

## 제목 범위를 정한 경우 ("2. 사업 개요 부분만", "처음부터 2장 전까지") — 자세히 모드
위 순서에서 3·6단계만 바꾼다. 범위는 문서의 제목(#) 줄로 정한다.

| 사용자 말 | 범위 값 |
|---|---|
| "2. 사업 개요 부분만" | `"2. 사업 개요"` (그 제목부터 같은 단계의 다음 제목 전까지) |
| "처음부터 2. 사업 개요 전까지" | `"~2. 사업 개요"` |
| "3장부터 5장 전까지" | `"3. 추진 배경~5. 추진 일정"` |

3. `node S/section_replace.mjs W/편집.md "<범위>" W/편집.md "이전=>새" ...`
   - 제목을 못 찾거나 여러 곳에 맞으면 종료 코드 1이고, 문서의 제목 목록이 나온다. 그 목록을 보여 주고 어느 제목인지 묻는다. 추측해서 고르지 않는다.
6. `bash S/check.sh -l W/patch.log -s "<범위>" ...` — 범위 밖에서 달라진 줄이 0, 범위 안 남은 이전 값이 0이어야 통과한다.
- 결과 파일 이름에 범위를 짧게 붙인다: `out/계획서_YYYY-MM-DD_사업개요.<확장자>`, `out/계획서_YYYY-MM-DD_사업개요_변경목록.md`
- 쪽 지정(`-p`)과 제목 범위(`-s`)는 같이 쓰지 않는다.
- 한계를 알린다: 장 제목이 장식 상자·표 안에 있거나 제목 스타일 없이 굵은 글씨로만 쓰였으면 제목으로 잡히지 않을 수 있다. 그때는 제목 목록에 없으니 사용자에게 보여 주고 다른 방법(쪽 지정, 긴 이전 값)을 묻는다.

## 사용자에게 알릴 것
- 한글 프로그램에서 열어 표와 글꼴을 눈으로 확인해 달라고 한다(자동 점검으로는 화면 모양까지 보지 못한다).
- 제목 장식 상자·글상자가 많은 양식은 일부 값이 건너뛰어질(SKIP) 수 있다. 점검에서 걸러진다.
