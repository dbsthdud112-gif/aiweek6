# 계획서 값 바꾸기

표 중심 한글 사업계획서(.hwp/.hwpx)에서 "이전 값 → 새 값"(연도, 날짜, 사업명, 금액 등)을 표·글꼴·이미지는 그대로 둔 채 한 번에 바꾸고, 바뀐 곳 목록과 자동 점검 결과를 만든다.

## 시작하기

1. bash(Windows는 Git Bash)와 Node.js(`npx`)를 준비한다. 한글 문서 처리 도구 kordoc은 처음 실행할 때 `npx -y kordoc@^4`로 한 번 내려받는다.
2. 프로젝트 폴더에 `raw/`를 만들고 바꿀 계획서를 넣는다.
3. 프로젝트 폴더에서 실행한다.

   ```bash
   bash 값바꾸기.sh raw/계획서.hwpx "2025년=>2026년" "5,000만 원=>6,000만 원"
   ```

4. "자동 점검 모두 통과"가 나오면 `out/`에 결과 파일과 `…_변경목록.md`가 생긴다. 변경목록의 바뀐 줄을 하나씩 확인하고, 결과 파일을 한글 프로그램에서 열어 표·글꼴을 눈으로 확인한다.

정한 쪽만(`-p 1`) 또는 정한 제목 범위만(`-s "2. 사업 개요"`) 바꾸는 방법은 아래 [사용법](#사용법)에 있다.

## 확인한 한계

- **장식이 있는 양식**: 제목 상자나 장 제목 띠(표)가 있는 양식에서는 표 안의 값을 반영하지 못했다(2026-10-10). 점검이 실패로 거르지만, 이런 양식은 지금 바꿀 수 없다. 실제 계획서가 이런 양식인지는 〔확인필요〕.
- **10분 목표**: 명령 실행 시간(19~30초)만 쟀다. 사람이 값을 정하고 결과를 확인하는 시간까지 합친 시간은 아직 재지 않았다.
- **잘못 바뀐 곳 0건**: 한글 파일 시험에서는 Claude가 바뀐 줄을 읽어 확인했고, 사용자 확인은 〔확인필요〕.
- **한글 프로그램에서 열어 보기**: 하지 않았다.
- **쪽 나눔**: 여기서 "쪽"은 kordoc이 그린 쪽이다. 한글 화면의 쪽과 다를 수 있다. 쪽 경계에 걸친 문단에 이전 값이 있으면 바꾸지 않고 멈춘다.
- **제목 범위**: 장 제목이 장식 상자·표 안에 있거나 굵은 글씨로만 쓰였으면 제목으로 잡히지 않을 수 있다. 실제 계획서에서는 〔확인필요〕.
- **.hwp 결과**: .hwp를 넣으면 결과도 실제로는 .hwp 형식이라 같은 확장자로 저장한다. .hwpx만 구조 검사(`validate`)를 한다.
- **다루지 않는 파일**: 워드(.docx)와 암호가 걸린 한글 파일은 다루지 않는다.
- **시험 범위**: 실제 계획서는 1개, 연도 두 종류로만 시험했다. 다른 운영체제에서는 시험하지 않았다.
- **기록의 해시**: 2026-10-17에 시험 자료의 전화번호를 실제로 없을 번호(국번이 0으로 시작)로 바꾸면서 `out/`의 일부 결과 파일 안 번호를 도구 없이 직접 고쳤다. 그래서 검증결과에 적힌 해시는 고치기 전 기준이다.

> 이 저장소에는 실제 계획서가 없다. 시험 결과(`out/`)는 모두 지어낸 가짜 계획서로 만든 것이고, 시험용 원본을 둔 `raw/` 폴더는 공개하지 않는다(`.gitignore`).

## 목적

사업계획서를 쓸 때마다 예전 계획서 내용을 옮겨 붙이고 문장·숫자·날짜를 하나씩 고치느라 내용 작성에만 반나절(3~5시간)이 걸린다. 그중 숫자·날짜 고치기가 1시간 이내다. 이 도구는 **숫자·날짜 고치기를 10분 이하**로 줄이는 것을 목표로 한다. (`01_페인포인트.md`)

- 하는 일: 이전 값을 한 번에 새 값으로 바꾼 새 한글 파일과, 어디가 바뀌었는지 보여 주는 목록을 만든다. 문서 전체, 정한 쪽만, 정한 제목 범위만 바꿀 수 있다.
- 하지 않는 일: 워드(.docx)·암호 걸린 파일, 바꿀 값 없이 숫자·날짜 찾아 표시하기, 문장 고치기, 서식 맞추기, 공고문 대조, 제출 양식 점검. (`02_기획안.md` › 범위)
- 원본은 읽기만 하고, 결과는 항상 `out/`에 새 파일로 만든다.
- 시험한 환경: Node v24.21.0, kordoc 4.18.13 (`plan.md`)

## 사용법

### 1. 터미널에서 직접 돌리기 — 문서 내용이 Claude에게 가지 않음

```bash
bash 값바꾸기.sh raw/계획서.hwpx "2025년=>2026년" "5,000만 원=>6,000만 원"
bash 값바꾸기.sh -p 1 raw/계획서.hwpx "2025년=>2026년"
bash 값바꾸기.sh -s "2. 사업 개요" raw/계획서.hwpx "2025년=>2026년"
```

| 옵션 | 뜻 |
|---|---|
| (없음) | 문서 전체 |
| `-p 1`, `-p 2-4`, `-p 1,3` | 정한 쪽에서만 바꿈 |
| `-s "2. 사업 개요"` | 그 제목부터 같은 단계의 다음 제목 전까지 |
| `-s "~2. 사업 개요"` | 처음부터 그 제목 전까지 |
| `-s "3. 추진 배경~5. 추진 일정"` | 3장부터 5장 전까지 |

- `-p`와 `-s`는 같이 쓸 수 없다.
- 결과: `out/계획서_날짜[_범위].<확장자>`, `out/계획서_날짜[_범위]_변경목록.md`. 같은 이름이 있으면 `_v2`, `_v3`를 붙인다.
- 자동 점검에 실패하면 결과 파일은 저장하지 않고 `out/…_점검실패.md`에 이유만 남긴다.
- 종료 코드: 0 성공, 1 실패(점검 실패 포함), 2 사용법 오류

### 2. Claude Code에게 맡기기

이 폴더에서 Claude Code를 열고 "1쪽만 2025년을 2026년으로 바꿔 줘"처럼 요청하면 스킬 `.claude/skills/계획서-값바꾸기/SKILL.md`를 따른다.

- **조용한 모드(기본)**: Claude는 위 `값바꾸기.sh`를 돌리고 그 출력(진행 단계, 통과·실패, 바뀐 줄 수, 결과 경로)만 읽는다. 변경목록은 열지 않는다.
- **자세히 모드**: 사용자가 "자세히 보여 줘"라고 할 때만 바뀐 줄을 읽는다.
- kordoc은 파일을 외부로 보내지 않지만, **Claude가 읽은 내용(바꿀 값, 건수, 필요하면 바뀐 줄·제목 목록)은 대화로 Claude에 전달된다.** 내용을 전혀 보내고 싶지 않으면 1번처럼 터미널에서 직접 돌린다.

### 3. 결과 확인 (사람이 할 일)

- `out/…_변경목록.md`의 바뀐 줄을 하나씩 보고, 잘못 바뀐 곳(예: 전화번호 속 2025)이 없는지 체크칸에 표시한다.
- 결과 파일을 한글 프로그램에서 열어 표·글꼴·정렬을 눈으로 확인한다. 자동 점검으로는 화면 모양까지 보지 못한다.

### 참고: 첫 버전 화면 (.txt/.md용)

`out/계획서_값바꾸기.html`은 한글 파일 방식으로 바꾸기 전에 만든 브라우저 화면이다. .txt/.md 파일만 받으며, 기록용으로 남겨 두었다.

## 확인한 결과

모두 지어낸 가짜 계획서로 시험했다. 전화번호 속 `2025`, `2,025만 원`, `2024년` 같은 함정 값을 넣어 두고, 이 값들이 바뀌지 않는지 함께 봤다.

| 날짜 | 시험 | 결과 | 기록 |
|---|---|---|---|
| 2026-10-06 | 첫 버전 화면(.md), 값 3개 | 남은 이전 값 0, 건수 11=11·3=3·2=2, 바뀐 줄 16줄 모두 확인 | `out/검증결과_2026-10-06.md` |
| 2026-10-06 | 한글 파일 문서 전체, 값 3개 | 남은 이전 값 0, 건수 6=6·8=8·2=2, 표 줄 33→33, 바꾼 곳 말고 달라진 줄 0, 건너뛴 곳 0, 구조 검사 통과, 명령 실행 20초 | `out/검증결과_2026-10-06_한글.md` |
| 2026-10-06 | 1쪽만 (5쪽 문서) | 1쪽 2025년 9→0, 2~5쪽 그대로, 쪽 수 5→5, 바뀐 줄 8줄 | `out/검증결과_2026-10-06_쪽지정.md` |
| 2026-10-06 | `2. 사업 개요`만 | 범위 안 3=3·1=1, 범위 밖에서 달라진 줄 0 | `out/검증결과_2026-10-06_제목범위.md` |
| 2026-10-06 | `값바꾸기.sh` (세 모드) | 문서 전체 11줄·1쪽 8줄·사업 개요 3줄 모두 통과, 결과가 스킬로 만든 결과와 같음 | `02_기획안.md` › 검증 |
| 2026-10-06 | 사용자의 실제 계획서(.hwp) 1개, 연도 두 종류 | 남은 이전 값 0, 건수 5=5·4=4, 표 줄 18→18, 병합 표 8→8, 이미지 11개 유지 (파일은 공개하지 않음) | `02_기획안.md` › 검증 |
| 2026-10-10 | 처음 보는 양식(제목 상자·장 제목 띠) | **실패**: 11곳 중 1곳만 바뀜, 표 4개 건너뜀. 점검이 실패로 걸러 결과를 저장하지 않음 | `out/검증결과_2026-10-10.md`, `out/계획서_2026-10-10_점검실패.md` |

자동 점검이 일부러 넣은 잘못을 잡는지도 확인했다. 바꾸지 않은 파일, "0개 변경" 로그, 확장자와 실제 형식이 다른 결과, 정한 쪽·범위 밖을 바꾼 결과, 없는 제목, 여러 제목에 맞는 말은 모두 실패하거나 멈췄다.

## 파일

| 경로 | 내용 |
|---|---|
| `값바꾸기.sh` | 터미널에서 직접 돌리는 명령 |
| `.claude/skills/계획서-값바꾸기/` | 스킬 지침(`SKILL.md`), 점검(`check.sh`), 바꾸기 스크립트(`replace.mjs`, `page_replace.mjs`, `section_replace.mjs`, `range.mjs`) |
| `out/` | 시험 결과: 계획서(.hwpx), 변경목록, 검증결과, 점검실패 기록, 첫 버전 화면 |
| `01_페인포인트.md`, `02_기획안.md` | 문제 정의, 기획, 검증 기준과 시험 기록 |
| `plan.md`, `기록.md`, `5주차_기록.md` | 구현 체크리스트, 진행 기록, 수업 기록 |
| `CLAUDE.md`, `check_rules.sh` | 작업 규칙과 그 확인 스크립트 |
| `docs/index.html` | 목적, 사용법, 확인한 결과와 한계를 담은 소개 페이지 |
